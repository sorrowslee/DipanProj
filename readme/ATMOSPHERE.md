# 場景氛圍後處理 (Atmosphere Post-Process)

> 返回 [文件總覽](README.md)

讓不同地圖有不同「調性」的全螢幕後處理：室外白天維持正常，走過傳送點進到古墓就自動變陰森。**由資料驅動**——每張地圖的氛圍型別寫在 `MapsTable.csv` 的 `Atmosphere` 欄，跟相機的 `MapMode` 同一套思路。

採 **Built-in 算繪管線**的全螢幕後處理（`OnRenderImage` + `Graphics.Blit`），不依賴 URP 2D 燈光，也沒動到專案既有的自訂 shader。


> **氛圍旁通（`AtmosphereController.SetBypass(0~1)`）**：可以把整套氛圍**暫時**與原始畫面內插（1＝完全還原原始畫面）。
> 在 `Atmosphere.shader` 的最後一行統一處理，所以不管哪個 mode 都一致地淡掉——**連天氣與提燈光圈一起**。
> 目前唯一呼叫者是**劇情演出的回憶特效**（幽暗地圖上畫面幾乎全黑，任何乘法式的色調效果都會失效，
> 見 [PROBLEMS.md](PROBLEMS.md) **J4**）。要做其他「暫時脫離現在這個場景」的演出可以沿用。

## 型別（MapsTable.csv 的 `Atmosphere` 欄）

分系：**陰森系（2/3）**用提燈光圈把玩家身邊壓出一小圈可見區；**末日炎熱系（4/5/6）**不壓暗、改暖色調並帶「熱浪扭曲」；**海洋系（7/8/9）**藍綠水色 + 「水下折射晃動」，深海+恐怖再套潛水燈光圈；**山頂風系（10/11）**——10 風雪（陰冷暴風、翻騰白霧 + 橫向風絲）、11 強風（去白霧、只留單一斜向風絲）；**雨系（12/13）**——12 綿綿細雨、13 大雨（近垂直雨絲往下落）；**陰森森林鬼霧（14）**——畫面偏暗、陰綠冷調 + 漂移黑霧，偶爾飄來一陣濃霧；**電視雜訊（15）**——雪花噪點 + 掃描線 + 滾動同步條 + 偶發水平撕裂；**室內系（16~19）**——給有屋頂的場景用的四種調性，共用同一段基底、只差幾個常數，見〈室內系〉。

## 室內系（16~19，2026-09-02 加）＋ Bloom 管線

給「有屋頂的場景」用的四種調性。**四種共用 shader 裡同一段基底**，彼此只差七個常數
（`Atmosphere.shader` 的 `_Mode > 15.5` 分支）：

| 常數 | 意義 | 16 暖光 | 17 金輝 | 18 冷月 | 19 燭火 |
|---|---|---|---|---|---|
| `dim` | 整體亮度（有燈處會還原） | 0.94 | 1.0 | 0.80 | 0.72 |
| `desat` | 去飽和量 | 0.05 | 0.05 | 0.30 | 0.15 |
| `vigDepth` | 角落壓暗深度 | 0.50 | 0.15 | 0.35 | 0.50 |
| `bloomK` | Bloom 疊加強度（會乘上 `litTint`） | 0.70 | 0.15 | 0 | 0 |
| `breathK` | 暗部呼吸幅度 | 0 | 0 | 0 | 0.03 |
| `lightW` | 色彩內插依據 | 0＝像素亮度 | 0 | 1＝照明係數 | 1 |
| `pivot` | **翻色分界**（Linear 亮度） | 0.085 | **0.140** | －(不用) | －(不用) |
| `split` | 過渡帶半寬（Linear） | 0.060 | 0.050 | －(不用) | －(不用) |
| `stoneLift` | 石材提亮 | 0 | 0.20 | 0 | 0 |
| `baseTint`／`litTint` | 暗處色／亮處（或燈池）色 | 暖／更暖 | **冷藍／金** | 灰藍／暖 | 中性偏冷／暖 |

**想調哪一種就改那一組常數**；要再加第五種室內氛圍，**照樣只加一組常數、不要另開分支**——
這支 shader 已把 19 種氛圍攤平、指令數吃緊，每多一段重複的式子都在逼近編譯上限（洋紅）。

- **⚠⚠ `pivot`／`split`／bloom 門檻都是 Linear 空間的數字**，不是看截圖估的亮度。專案跑 Linear：
  截圖上 0.32 的中間灰，shader 裡的 `lum` 只有 **0.083**；實測石材大廳的 linear 分布是
  `p25=0.055 / p50=0.083 / p90=0.135 / p99=0.20`——**整張畫面都擠在 0.02~0.20**。
  憑直覺填 0.5 那種「一半亮」的門檻，結果是 `litTint` 完全不參與、bloom 恆為 0，
  **症狀是「效果好像沒做」而不是報錯**（16/17 為此白調了一輪，見 [PROBLEMS.md](PROBLEMS.md) **E26**，
  那裡附了量 linear percentile 的程式碼片段）。要重定門檻就量一張該場景的截圖，別用眼睛估。
- **`pivot` 是「翻色分界」，不是「中間調中心」**：要「中間調維持底色、只有亮部才轉色」（17 的冷石材＋金高光），
  分界要放在**中間調之上**（p85~p90＝0.14）；放在中位數等於把一半畫面判給高光色，整張圖變成高光色、
  又跟隔壁 mode 混在一起（16/17 第三版才修對）。要「整張同一個調性」（16 的暖）就放中位數。
- **Bloom 疊加時會乘上該 mode 的 `litTint`**：bloom 抽的是場景原色，石材偏暖褐，不染色的話光暈會把 mode 自己的
  調性沖掉（17 的冷調就是這樣被沖成暖的）。光暈的顏色本來就該是該 mode 的高光色。
- **`split` 決定兩個 mode 拉不拉得開**（2026-09-02 首版實測補上）：亮度路徑**不能直接拿 lum 當權重**。
  一般場景大半是中間調（灰石材 lum≈0.55~0.6），直接用等於全畫面停在內插中點，色調不同的兩個 mode
  會算出幾乎同一個顏色——16/17 首版就是這樣，實機看不出差別（見 [PROBLEMS.md](PROBLEMS.md) **E26**）。
  現在走 `smoothstep(0.5-split, 0.5+split, lum)`：**split 小＝曲線陡**（中間調歸到暗側，只有真正的亮部才轉暖／金）
  ＝冷暖分離明顯；**split 大＝平緩**（整張圖同一個調性）。**覺得兩個 mode 太像，先動 `split`，不要先動顏色。**
- **`lightW` 是這段設計的關鍵**：它決定色彩往哪邊內插。`0`＝按像素自身亮度（暗部冷、亮部暖／金，
  **不需要場上有燈**，16/17 用）；`1`＝按照明係數 `v`（燈池暖、其餘冷＝冷暖對比，18/19 用，**必須有燈**）。
- **16/17 刻意不吃照明**（不在 `BuildLights` 白名單）：它們的「中央較亮」是暈影做出來的，零成本。
  ⚠ **代價**：暈影的「中央」是**螢幕**中央。室內房間常常不到 18×10、走「整張地圖」相機模式，
  這時中央＝地圖中央，玩家走到角落會覺得自己站在暗處。要改成「玩家周圍亮」，把 16/17 加進
  `BuildLights` 的白名單（一行），但那些地圖就得實際擺吊燈／燭台的光源點。
- **17 的「石材略提亮」是近似**：後處理拿不到材質資訊，靠「低飽和 ＋ 中高亮度」猜石頭。
  同樣低飽和的灰衣服、鐵器也會被一起提亮。
- **19 的呼吸**用兩個不同頻率的 sin 疊加（單一 sin 有機械感），幅度 ±3% 且只作用在 `1-v`（沒被燈照到處）
  ——全螢幕同步明滅看久會暈。每盞燈**自己**的搖晃是另一回事（`LightSource.Breathe`，CPU 端各自算），
  兩者疊起來才是「燭火感」。

### Bloom（只有 16/17 會跑）

Bloom 不做在主 shader 裡：它的「柔」來自大模糊半徑，而半徑一大、tap 數不跟著加就只是重影
（[PROBLEMS.md](PROBLEMS.md) **J5** 的通則），塞進單 pass 要三十幾個 tap，很容易撞編譯上限。
改成 `AtmosphereBlit` 在主 Blit 之前跑兩個降解析度的小 pass（`Resources/Shaders/AtmosphereBloom.shader`）：

0. **先做一次無材質 `Graphics.Blit` 到 1/2**——硬體 bilinear 縮一半時本來就會平均 2×2，等於**免費的 box filter**。
1. **pass 0（1/2 → 1/4）**：4-tap box + soft-knee 亮部抽取。合計覆蓋原始畫面 **8×8**。
   **逐級 2x 是抗鋸齒的關鍵**：一次從全解析度跳到 1/4，就算塞 9 個 tap 覆蓋也只有 4×4，殘留的 moiré
   會在相機移動時整片爬行（首版 4-tap、二版 9-tap 都栽在這裡，見 [PROBLEMS.md](PROBLEMS.md) **E27**）。
   threshold 刻意放在這一級而不是全解析度那級——它是非線性運算，作用在高頻資料上會把微小亮度差
   放大成「有／沒有」，自己製造閃爍。
2. **pass 1（1/4 → 1/8）**：9-tap tent 模糊。在 1/8 上的 9 tap 才等效於全螢幕的一大片。
3. 主 shader 用一次雙線性取樣放大加回（**放大本身就是免費的額外柔化**），且是**加法**——
   乘法類效果在暗畫面會安靜失效（J4），而 bloom 的本質就是亮處溢出來。

合計約 0.64 次全螢幕取樣的量級——**多一級反而比單級塞更多 tap 便宜**，也比在單 pass 內硬做便宜得多。
`BloomEnabled` 只在 mode 16/17 為 true，其餘 17 種氛圍完全不經過這兩個 pass、成本與加這功能之前一模一樣。
**門檻定在 0.09（Linear）**：畫面 linear 亮度 p50≈0.083、p99≈0.20，門檻設 0.45 甚至 0.62 等於整張圖都過不了、
bloom 恆為 0（前兩版都是這樣，看起來像沒做）。0.09 貼著中位數，讓「亮於平均的地方」開始溢光——
室內系是亮場景，bloom 要的是**「光瀰漫」不是「亮點溢出」**，門檻本來就該貼著中位數。
調 bloom：強度改 `Atmosphere.shader` 那組常數的 `bloomK`；門檻／柔邊／擴散改 `AtmosphereBloom.shader`
的 `_Threshold`／`_Knee`／`_Spread` 預設值（材質是 `new Material(shader)`，吃 Properties 的預設值）。
載不到 bloom shader 時只會少掉光暈，色溫與暈影照常（會印一行 Warning）。

## 場景主色染色（AtmoTint 欄，2026-08-28 加；美術紀律一「色彩劇本」）

把整張畫面的**暗部**往地圖主色的色相拉，讓暗從「灰的暗」變「有主題的暗」（紅嫁衣＝暗絳紅的暗）。
`MapsTable.csv` 的 **`AtmoTint`** 欄（第 13 欄）：6 碼 `RRGGBB`（不含 `#`），**留空／缺欄＝不染（舊行為）**。

- **只動色相/飽和、亮度不變**：shader 端把 tint 歸一化到像素自身亮度再內插——不會把畫面再壓暗（E11 守則）。
- **按暗度加權**：暗部染最重、亮部（燈池中心、自發光、紅燈籠）幾乎不動＝自帶「強調色保護」。
- **疊加位置**：所有 mode 分支之後、`_Bypass` 內插之前 → 任何氛圍都可疊、回憶演出照樣整套淡掉。
- **任何地圖都可用**：「Atmosphere=1 且 EnvBright=100」的圖填了也會生效（controller 會為此啟用後處理；
  此時照明清單刻意不收集，見 `BuildLights` 檔頭註解，否則佛燈會在大白天染出一圈暖色）。
- 整體強度＝`AtmosphereController.SceneTintStrength`（現 0.32；首版 0.5 實測連中間調都被拉、整片粉紗）；暗度權重曲線在 shader 的 `_TintAmount` 段（現 smoothstep 0.04~0.42，只染真正的暗部）。
- 目前紅嫁衣全 10 張圖填 `5A2430`（暗絳紅）。
- ⚠ **編輯器的「照明預覽」不模擬染色**（它只鏡像 type 1 的壓暗＋照亮式子）——調 AtmoTint 以實機為準。

## 玩家常駐體光（2026-08-28 加；美術紀律二「主角永遠看得見自己」）

暗場景（2/3/9、或 EnvBright<100）裡玩家**沒有任何發光裝**時，自動補一圈「快熄的香頭」等級微光：
半徑 1.2 格、亮度 0.35、恆定不呼吸、瀰漫柔邊——**只照出自己的身體輪廓，照不了路**，
所以柴房教學「要點燈才看得見路」的壓力不變。裝上佛燈後由佛燈光圈取代（不疊加）。
光色是**偏中性的微暖白**（刻意與火把暖橘區隔：體光是「角色可讀性」不是「一盞燈」）。
常數在 `AtmosphereController` 檔頭（`PlayerAmbient*`），嫌亮嫌暗改那裡。

## 怪物常駐體光（2026-09-04 加）

暗場景裡怪物整隻沉在黑色中、連輪廓都看不出來（作者實機回報，紅嫁衣女殭屍也一樣）。
**每隻怪生成時自動掛一盞很小的 `LightSource`**，用途與玩家體光完全相同——照不了路，只讓輪廓浮出來。
**體光是兩層疊起來的**，兩層互補、缺一不可：

| 層 | 元件 | 機制 | 做什麼 | 侷限 |
|---|---|---|---|---|
| ① 環境照明 | `LightSource` | **乘法**（把 Atmosphere 的壓暗還原） | 讓怪**周圍的地面**亮一點，有被光照到的感覺 | **深色地板上幾乎無效**（見下方警告） |
| ② 加色光暈 | `CharacterGlow` | **加色**（`Custom/AuraGlow`，`Blend One One`） | 保證**輪廓**在任何地板上都看得見 | 不會照亮周圍地面 |

①：半徑 1.2 格（×CSV 的 `Scale`）、亮度 0.35、恆定不呼吸、瀰漫柔邊。
②：畫在角色**之下**（sortingOrder −1）⇒ 只有角色 sprite 的透明區亮起來，是「剪影浮出來」不是「整隻怪發光」；
直徑 = 可見高度 ×1.35，亮度 0.11。
> ⚠ **目標是「不要完全被黑暗吃掉、勉強看得到輪廓」，不是給怪一盞跟著跑的燈。**
> 2026-09-04 第一版設 0.30／×1.9，實機回報「根本變成行動燈光」。這兩個值寧可偏低，往上調要很小步。兩層都用**陰冷青白**——與玩家的微暖白區隔，一眼分得出敵我。
**適用所有怪物、所有地圖**，不是某個關卡的特例。

> ### ⚠ 為什麼非要第二層不可（2026-09-04 實機踩到）
> `LightSource` 那套光是**乘法**——type 2 幽暗在 shader 裡是 `col.rgb *= lerp(0.35, 1.0, v)`，
> 光的作用是「把壓暗**還原**」而不是「加光」。所以光圈亮不亮**完全取決於該處原本的畫面有多亮**：
> - 淺色石板地（原亮度 ~0.5）：`0.175 → 0.33`，光圈很明顯
> - 新娘房的深色木地板（原亮度 ~0.15）：`0.053 → 0.099`，兩個都是「很暗」，**肉眼分不出來**
>
> 實機上就是這樣：同一份程式、log 證實都掛上了（r=1.5 i=0.55），一般房間的怪很亮、
> 新娘房的 boss 完全看不見，**差別只在腳下地板的顏色**。而且**再怎麼調 `intensity` 都沒用**
> ——0.55 調到 1.0 也只是把 0.15 還原成 0.15。
> 這與 `MemoryFxController` 檔頭記的是同一條通則：**在黑色上乘任何顏色還是黑**。
> 要「不管背景多暗都看得見」，就只能用加色。

> ⚠ **不要把它調回跟玩家體光一樣的數值**（半徑 1.2／亮度 0.35）。第一版就是照抄玩家的，
> 結果實機上「看起來像沒有光圈」。兩者的目的不同：玩家體光要的是「微弱到照不了路」——玩家本來就
> 知道自己在哪，只需要一點提示；**怪物要的是被「認出來」**，那是高得多的門檻。在幽暗（type 2，
> 壓暗 0.8）的場景裡，0.35 的亮度只把 0.2 的底亮提到 0.3 上下，肉眼幾乎讀不出輪廓。

- 嫌怪在暗處看不清楚時，**該調的是 `MonsterGlowAdditive`（加色光暈，預設 0.30）**，不是 `MonsterGlowIntensity`。
- **掛點有兩處，兩邊都呼叫同一個 `MonsterSpawner.AttachMonsterGlow`（方法自己判重、不會掛兩顆）**：
  - **正規入口 `MonsterSpawner.SpawnMonster`**——知道 CSV 的 `Scale`。常數（`MonsterGlow*`）就在那支檔案裡，嫌亮嫌暗改那裡。
  - **保險 `MonsterController.Start`**——和 `BlobShadow`／`YSortByFeet` 並列，**每隻怪一定會跑到**，
    接住任何沒經過 `SpawnMonster` 的生成路徑（2026-09-04 加：新娘房 boss 與召喚物實機沒有光，
    走查所有已知路徑都該經過正規入口卻對不上，所以補這一道）。
- ⚠ **NPC 必須排除**：**NPC 沿用整套怪物地基**（`NpcSpawner` 一樣 `AddComponent<MonsterController>`，
  連 `BlobShadow`／`YSortByFeet` 都是靠 `MonsterController.Start` 掛的），不擋掉的話 NPC 會跟著發鬼光。
  保險那一道用 `GetComponent<NpcAgent>() == null` 擋。
- ⚠ prefab **自帶 `LightSource` 的怪不會被覆蓋**（設計上就會發光的怪，尊重它原本的設定）。
- ⚠ 它跟場景的燈**共用同一個 20 盞名額**。排序鍵是「距離 − 半徑」，體光半徑很小，遇到半徑大的
  場景燈天生排在後面 ⇒ 不會擠掉燈籠火把；但反過來，**某張圖若擺了非常多盞燈，怪物體光可能進不了前 20 名**。
  症狀是「這張圖的怪就是沒有光」，先去數那張圖的發光地上物。

### 除錯：按 F9 印出這一幀真正餵給 shader 的光源

光「看起來沒作用」時，可能的原因有好幾層——**這張圖的氛圍根本不吃照明**／光源沒被掛上／
被 20 盞名額擠掉／掛上了但參數太弱看不出來。**光看畫面分不出是哪一種。**
Play 中按 **F9**，Console 會印一次快照：氛圍 type、吃不吃照明、本幀盞數，
以及每一盞的**來源物件名、世界座標、半徑、亮度、柔邊、搖晃**（依「距離−半徑」排序，
排在 20 名之後的不會進畫面）。程式在 `AtmosphereController.DumpLightsIfRequested`。

另外 **Editor 下每掛上一盞怪物體光都會印一行 `[MonsterGlow] 掛上體光：<物件名> r=… i=… pos=…`**
（`#if UNITY_EDITOR`，不進 build）。要確認「某隻怪到底有沒有掛上」時看這個最快——
沒印到就是那隻怪的生成路徑沒被涵蓋，印了但畫面沒光就是被名額擠掉或參數太弱（再按 F9 分辨）。

> 同家族的除錯工具：`P` 效能面板（面板中再按 `C` 疊碰撞層）、`F8` 關卡進度。

**傳送點冷光（2026-08-28 加）**：每個傳送點標記（VfxTable id 6）自動掛一盞**冷藍**微光
（半徑 1.6、亮度 0.5、極輕微搖晃），暗場景在傳送點周圍照出冷光池——與滿場暖橘形成色溫對比，
玩家一眼找到出口；亮場景照明不收集、零影響。全遊戲規則：**傳送點＝冷色、火光＝暖色**。
參數在 `MapLoader` 的 `teleportLight*` 欄位（`teleportLightRadius = 0` 可整個關掉）；
掛在標記物件上，`togglePortal` 隱藏與換圖銷毀時自動熄滅。

## 角色環境融合（2026-09-03 轉正；前身 09-02 的 CharacterEnvPoc）

**問題**：全螢幕後處理對角色與場景一視同仁，永遠不會改變「角色暗部比場景暗多少」——亮場景裡角色黑衣服是死黑、地板卻是中灰，人眼就判定角色是貼上去的（大廳實測地板 linear 中位 0.36、角色暗部 0.02，差 18 倍）。只能在角色自己的 sprite 上動。

**做法**（`Scripts/Atmosphere/CharacterEnvFusion.cs` ＋ `Custom/SpriteFlash` 的 `_Env*` 參數）：
- **黑階抬升**（主角）：角色最暗處抬到「場景中位 ÷ 14」（`TargetDarkRatio`，作者實機拍板：大廳 ×1 剛好、×2 太過；上限 `MaxBlackLift` 0.06）。抬升量帶場景暗部的顏色，不然角色暗部會被拉得比場景冷。
- **環境色**（輔）：角色暗側乘場景暗部的歸一色、亮側乘場景亮部的歸一色，強度 0.35。
- **自動算，不做每種氛圍一組參數**：會隨場景變的只有「中位亮度」與「暗部／亮部顏色」，全部**進圖後量最終畫面**——`AtmosphereBlit` 在後處理之後把整個畫面逐級縮到 32×18、`AsyncGPUReadback` 讀回 CPU（不卡幀），算中位亮度、最暗 15% 平均色、最亮 15% 平均色。換圖後第 20 幀量一次、第 110 幀再量一次（分幀載入、光源都到位後），之後不再量。這是 PROBLEMS **E26**「量最終畫面、不要照 shader 常數推」的自動化版本。
  - 結果：大廳（17）≈0.026、紅嫁衣暗房（2，地板中位 0.016）≈0.001＝等於不抬。**場景越亮抬越多、暗到像紅嫁衣就自動關**。
- 參數走 `MaterialPropertyBlock`，由 `HitReactionHandler` 與白閃寫在**同一個 block**（`SetPropertyBlock` 整包覆蓋，分兩處寫會互相洗掉）。全部 0 時 shader 整段跳過＝逐位元等於沒這功能。

**怎麼看／怎麼調**：P 面板 **G** 循環 0 原狀／1 自動／2 自動×2，**Shift+G** 重量一次場景；按鈕上顯示量到的場景中位亮度、量測次數、主角實際拿到的抬升量。全域力道只有一顆 `TargetDarkRatio`（14；越小越亮）。要單張圖覆寫：MapsTable 加 `CharLift` 欄（尚未加，需要時再加，空＝自動——同 AtmoTint 慣例）。

**已證偽、不要重做**（09-02 量的）：「角色沒參與 bloom」不成立；「邊緣對比是主因」不成立（Test C 已砍）。**解析度不一致**（背景被放大顯示）是另一個獨立且更大的根因，見 PROBLEMS **E29**。

## 運作方式

- **自動生成、零接線**：`AtmosphereController` 用 `[RuntimeInitializeOnLoadMethod]` 自生成、跨地圖常駐（同 PerfHud 模式），每場景把後處理元件 `AtmosphereBlit` 掛到 `Camera.main`。
- **地圖驅動**：`MapManager.LoadMapInternal` 載圖時呼叫 `AtmosphereController.ApplyMapAtmosphere(row.atmosphere)` 切換當前模式；換圖即時生效。
- **type 1**：控制器把 Blit 材質設 `null` → 直接 passthrough，等於關閉，零開銷。
- **type 2~15**：用同一個 shader `Custom/Atmosphere`，靠 `_Mode`（1~15）切換外觀。吃照明的（1+環境亮度、2/3/9/14）由控制器每幀餵入最近 20 盞燈的螢幕位置／半徑／光色／亮度，每盞半徑與亮度各自以**油燈式 Perlin 明滅**呼吸；炎熱（4/5/6）、海洋（7/8/9）、風系（10/11）、雨系（12/13）、鬼霧（14）、電視雜訊（15）在 shader 內以 `_Time` 做扭曲/風絲/雨絲/黑霧/雪花，不需控制器額外參數。
- **UI 不受影響**：後處理只作用在主相機算繪的畫面；Screen Space Overlay 的 HUD／面板在其後合成，不會被壓暗。

## 照明：多光源（2026-08-10 改；原為單光源 2026-07-22）

畫面的「照亮」由一份**光源清單**驅動，每幀取離**相機中心**最近的 **20 盞**餵給氛圍 shader（2026-08-28 改：基準原為玩家、上限原為 12——全圖一屏的樞紐房會超標且燈隨走位被踢，見 [PROBLEMS.md](PROBLEMS.md) **E23**）。
生效的氛圍：**2 幽暗 / 3 噩夢 / 9 深海恐怖 / 14 陰森森林鬼霧**，以及**任何 `Atmosphere=1` 但「環境亮度」<100 的地圖**（見下一節）。
其他氛圍（烈日、海洋、風雨、雜訊…）不吃照明。

光源有**四種來源**，一視同仁塞進同一份清單（都是 `LightSource` 元件）：

1. **玩家身上的發光裝**：掃 6 個裝備欄取最大的 `LightRadius`（>0 就以玩家為心）。目前只有佛燈（id 8）。卸下就沒有。
2. **獨立光源**（`map.lights`，編輯器「照明」分頁）：**不綁任何地上物**的照明點。
   給「火炬／燈籠**已經畫在背景圖裡**」的情況——不必為了發光把它們從背景拆成地上物，把光源點放到火焰中心即可。**這是擺場景照明的主力**。
3. **地上物自帶的燈**（`ObjectInstance` 的照明六欄）：適合「本身就是一個可撿／可破壞物件」的燈，例如柴房地上的佛燈——**撿走（物件銷毀）光就自動跟著消失**。
4. **角色常駐體光**（不是擺出來的燈，是「讓角色在暗處看得見輪廓」的機制）：玩家的見〈玩家常駐體光〉，怪物的見〈怪物常駐體光〉。

> 兩種放置方式沒有優劣，差別只在「光要不要跟著某個物件的生死」。
> 大多數場景照明用 ②；只有「這盞燈本身是個能互動的東西」才用 ③。

沒有任何光源 → 全暗（暗場景沒燈就看不見，逼玩家點燈）。

**疊合方式**：多盞燈在 shader 內用 screen 疊合（`v + vi − v·vi`），兩圈交界自然變亮、不會有硬邊。
**顏色**：各盞光色以亮度加權平均後做「亮度歸一」再套用 → **只染色相、不改明暗**，所以鬼火照出來是青綠、火把是暖橘，但不會因為換色就變亮或變暗。

> ⚠️ 同框上限 20 盞是 `AtmosphereController.MaxLights` 與 shader 的 `MAX_LIGHTS` 兩邊寫死的常數，**改一邊一定要改另一邊**（編輯器 `LightPreview.GameMaxLights` 警告門檻也要跟）。超過 20 盞時，離相機中心最遠的會被丟掉（排序鍵是「距離 − 半徑」，所以遠處一盞大燈不會被近處的小燭火擠掉）。

### 怎麼擺一盞獨立光源

地圖編輯器頂部工具列 →「**照明**」→「＋ 新增光源」（生在畫面中心並直接進放置模式）→ 到畫布上點一下放到火焰中心。
之後**直接用滑鼠拖曳畫布上的燈就能移動**（跟拖地上物一樣）；也可「放置位置」精準重放、「複製一盞」（含所有參數，擺一整排同款火炬時用）、或在清單按「刪」。
建議搭配頂部列的「**照明預覽**」一起用——開著拖，明暗即時反應。

畫面上每盞燈畫成兩個同心圓 ＋ 中心十字（光源本身沒有圖，沒有十字不知道該點哪裡）。
「名稱」欄只是給清單好認（例：「大廳左火炬」），遊戲端不讀。

### 每盞燈的欄位（獨立光源在「照明」面板；地上物的燈在地上物面板、發光半徑 >0 才展開）

| 欄位 | 意義 | 預設 |
|---|---|---|
| 發光半徑 | 照得到多遠（世界單位＝格）。0＝不發光，其餘欄位一律忽略 | 0 |
| 亮度 | 1＝標準；<1 微光（快熄的燭火）；>1 刺眼（爐火） | 1 |
| 光色 RGB | 6 碼 16 進位 `RRGGBB`（不含 `#`）。空＝預設暖橘 `FFC785` | 空 |
| 搖晃強度 | 0＝完全不動（電燈／月光）；1＝標準燭火；2＝狂亂火焰 | 1 |
| 搖晃速度 | 小＝油燈慢慢晃；大＝營火急促跳動 | 1 |
| 邊緣柔和 | 內圈(全亮)佔外圈的比例。小＝瀰漫柔邊；大＝範圍內均勻、邊緣硬（聚光燈） | 0.46 |

面板上有六顆**燈種預設**鈕（火把／燭火／燈籠／鬼火／月光／爐火）一鍵套好上面五個欄位（**不動發光半徑**，範圍自己定）。

**每盞燈的搖晃是各自獨立的**（各有自己的亂數種子）——單光源時代是全域共用一組呼吸，一整排火把同步明滅看起來很假，現在不會了。搖晃同時作用在半徑與亮度上（火焰變大時也變亮），比只縮放半徑自然。

世界半徑 → 螢幕光圈：正交相機下 `外圈viewport = worldRadius / (2 × orthographicSize)`，所以**同一盞燈在不同縮放的地圖，照亮的世界範圍一致**。

### 環境亮度：讓「正常」地圖也吃照明

`MapsTable.csv` 新增 **`EnvBright`（環境亮度）** 欄，0~100，**留空／缺欄＝100（完全不壓暗，與舊行為相同）**。
**只在 `Atmosphere=1`（正常）時生效**：把整張圖壓暗到這個亮度，場上的燈再把周圍照回來。
`Atmosphere>=2` 時忽略此欄（那些氛圍的暗度由氛圍本身定義）。

| 值 | 感覺 |
|---|---|
| 100 | 白天室外（不處理，shader 直接 passthrough） |
| 70 | 陰天／傍晚，火把微微有感 |
| 45 | 昏暗室內，火把明顯 |
| 25 | 只靠火把才看得見路 |

用途是「**不到幽暗／噩夢等級、但想讓火把有存在感**」的室內走廊、地窖、柴房。
比起直接把整張圖設成 `Atmosphere=2`，它不會去飽和、不會加冷色調，美術原本的顏色都在。

### 編輯器預覽（2026-08-10 補上實際明暗）

兩層東西，各解決一個問題：

**① 參考線 `Core/LightOverlay.cs`** —— 每盞燈畫成兩個同心圓（外圈＝照得到的範圍、內圈＝全亮範圍＝邊緣柔和度），
圈色＝光色，選取中的加黃框。獨立光源另有一個**把手**（圓＋十字），拖曳中會多畫兩圈變「實心」。
> ⚠ 把手大小必須與 `LightController.PickNearest` 的 `pickR` 一致（都是 `max(0.4, tileSize×0.5)`），
> 不然會出現「看得到把手卻抓不到」或「抓得到卻沒畫」。

**② 實際明暗 `Core/LightPreview.cs` ＋ `Resources/Shaders/EditorLightPreview.shader`** ——
頂部工具列「**照明預覽**」開關（放頂部列而不是照明面板，因為擺地上物、畫地磚時也會想開著看氣氛；狀態記在 PlayerPrefs）。
把場景壓暗、再讓場上的燈照回來，**改半徑／亮度／光色／搖晃、拖曳光源，畫面立刻跟著變**（含搖晃動畫）。

做法是**一張蓋滿相機視野的四邊形**，用相乘混合（`Blend DstColor Zero`）疊在所有地圖 sprite 之上，輸出
`lerp(1 − 環境壓暗, 1, 光照量) × 光色偏移` —— 與遊戲端 type 1 分支**完全同一條式子**。

> **為什麼不用相機後處理（`OnRenderImage`）**：編輯器的參考線（光圈、選取框、格線）畫在 `OnPostRender`，
> 那是在相機算繪之後、後處理之前——用後處理會把參考線一起壓暗看不清。
> 改成四邊形參與正常算繪，`OnPostRender` 的線就會蓋在它上面維持清楚。

> **sortingOrder 用 32766**：本專案 sortingOrder 實質是 16-bit（見 `SCENE_EFFECT.md`），大基底會繞回負值被背景蓋住。
> 32767 留給「顯示底部ui」參考層（那是對位用的，不該被壓暗）。

**預覽環境亮度**是編輯器本地的滑桿（0~100，PlayerPrefs 記住），**不會存進 `.dipanmap`**——
調到滿意後要**自己把數字填進 `MapsTable.csv` 那張圖的 `EnvBright` 欄**，遊戲裡才會一樣暗。

**與遊戲的兩個差異**（面板上也有寫）：
- 預覽只模擬「壓暗＋照亮＋光色」，遊戲的氛圍 2 幽暗／3 噩夢還會**去飽和、加冷色調**，實際更陰沉。
- 預覽最多畫 32 盞（`LightPreview.MaxPreviewLights`，與 `EditorLightPreview.shader` 的 `MAX_LIGHTS` 一致），
  遊戲同框上限 20 盞。**畫面內盞數超過 20 時面板會出示警告**（預覽比遊戲亮屬正常）。

### 「照亮圈」與「殺怪圈」是兩回事

佛燈（`Mode=Aura` 武器）使用時本身有一個 **`GroundEffect` 光環＝殺怪圈**（灼傷近敵）；這裡的**照亮圈**是氛圍後處理、只管「看得見多大範圍」，兩者半徑各自獨立：照亮圈可以放大（看得遠、不那麼壓迫），殺怪圈維持小（怪要靠近才燒得到，玩家不會太輕鬆）。想調哪個就調哪個，互不影響。

## 怎麼調

- **每張地圖選型別**：改 `MapsTable.csv` 該列的 `Atmosphere`（1~19）。室內 16／17／18／19；恐怖 3；末日炎熱 4／5／6；海洋 7／8／9；風雪 10、強風 11；細雨 12、大雨 13；鬼霧 14；電視雜訊 15。
- **光圈大小**：改**光源的世界半徑**——發光裝改 `ItemTable.csv` 的 `LightRadius`（佛燈 id 8＝3.5）、發光地上物改編輯器地上物面板的「發光半徑」。內外圈比例改該盞燈的「邊緣柔和」欄（預設 0.46）。
- **想讓亮場景的火把也有光**：把該地圖 `MapsTable.csv` 的 `EnvBright`（環境亮度）從 100 調低（45 是昏暗室內的好起點）。詳見上面〈照明：多光源〉。
- **各型別的調色／壓暗／冷暖／去飽和**：`Atmosphere.shader` 的 `frag` 內，type 2~9 各自一段的常數（如 type2 周邊亮度 `lerp(0.35,…)`、type5 橙紅 tint、type7 青綠 `float3(0.62,0.92,1.02)`+焦散、type8 深藍 `float3(0.30,0.50,0.85)`+水霧、type9 潛水燈 `lerp(0.04,1.0,v)` 等）。
- **扭曲強度/快慢**：熱浪（4/5/6）、水下折射（7/8/9）、風吹拂（10/11）各一段在 frag 頂部，調位移幅度（熱浪 `0.0014`、海洋 `0.0022`、風 `0.0016`）與頻率/時間係數。
- **風雪風絲/霧/陣風**（type 10）：風絲用 `windStreak(...)` 兩層疊（改 `scale`=密度、`speed`=快慢、整體 `* 0.07`=明顯度，段落隨機度在函式內 `step(0.55,…)`）；翻騰白霧改 `edge`（範圍）、`churn`（翻滾）與 `fog * 0.7`（濃度）；陣風節奏改 `gust` 的兩個 sin。
- **強風斜向風絲**（type 11）：兩層 `windStreak(rot2(i.uv, a), …)` 用**同一個角度 `a`**（只差密度/速度，不交叉）；改 `a`=風向傾角（正/負換邊）、`scale`/`speed`=密度/快慢、整體 `* 0.08`=明顯度；type 11 無白霧、幾乎不調色。
- **雨絲**（type 12 毛毛雨 / 13 大雨）：雨絲也用 `windStreak(rot2(i.uv, 1.50), …)`（近垂直），`speed` 為負＝往下落、`r=r*r` 收成銳利雨點。改旋轉角（越接近 1.57 越垂直）、`scale`=密度（越大越細密）、`speed`=落速、整體 `* 0.06`=明顯度。type 12 是在 13 之上把 `speed` 減半（-1.1）並用 `step(0.5, hash11(...))` 隨機丟掉半數雨列做半密度。
- **陰森森林鬼霧**（type 14）：底色在 `* float3(0.62,0.78,0.66)`（陰綠）、`* 0.70`（壓暗）、`lerp(0.40,…)`（暈影）。黑霧團＝每 `period`（24s）一團，從畫面外一側 `lerp(±0.6→∓1.6, cross)` 緩慢橫越，`cross = ph/0.83`（橫越時間＝`period×0.83`≈20s、其餘為空檔）。要更慢→等比放大 `period` 與 `0.83`；要更「偶爾」→只放大 `period`。霧團大小 `rad`、壓黑 `blob*0.85`、橢圓寬扁 `float2(q.x*0.6, q.y*1.3)`；方向/高度/大小由 `hash11(ci...)` 每團隨機。
- **電視雜訊**（type 15）：雪花混入量 `lerp(…, snow.xxx, 0.09)`、掃描線 `0.90 + 0.10*sin(uv.y*540.0)`（540＝線數）、同步條速度 `t*0.25`、閃爍 `sin(t*30.0)`、灰調 `lerp(…,lum,0.35)`、雪花更新率 `floor(t*24.0)`；水平撕裂在 frag 頂部位移段（`step(0.93,…)`＝撕裂機率、`*0.05`＝幅度）。
- **室內系（16~19）的調性**：改 `Atmosphere.shader` `_Mode > 15.5` 分支裡那四組常數（對照表見上面〈室內系〉）；
  Bloom 的門檻/擴散改 `AtmosphereBloom.shader` 的 Properties 預設值。
- **呼吸快慢/幅度**（type 2/3/9）：`AtmosphereController.cs` 的 `BreatheMin`/`BreatheMax` 與 `LateUpdate` 內 Perlin/sin 的係數。

## 備註

- 這是 Built-in 管線的覆蓋層方案，刻意不走 URP。若日後要「火把實際打光、牆會投影」那種逐光源互動，才需評估遷移 URP（會牽動既有自訂 shader）。
- **互動星星（拾取/劇情點的星星標示）刻意不被本後處理壓暗**：它們放在 `InteractOverlay` 層、由 `OverlayCameraController` 的疊加相機畫在後處理**之上**（暗場景也永遠可見，因為它是玩家的互動指引、性質同 UI 提示）。其餘世界物件（角色/怪/地上物）仍照常受壓暗。詳見 [INTERACTION.md](INTERACTION.md)〈暗場景也看得到星星〉。
- 設計沿革見 [PROGRESS.md](PROGRESS.md)。陰森系先前用 git 分支比較過 spotlight／full／colorgrade 三種雛形，整併成 type 2（= full-soft）與 type 3（= full）；末日炎熱系同樣分支比較 noon／ember／dust，整併成 type 4／5／6；海洋系（7/8/9）、山頂風系（10 風雪 / 11 強風）、雨系（12 細雨 / 13 大雨）、陰森森林鬼霧（14）、電視雜訊（15）直接加在 develop。
- 熱浪扭曲是全螢幕均勻的克制版微晃；若日後要更真實（只在地面/火源附近、或更強的地平線蜃景），可改成漸層遮罩或局部套用。
