## 0. 一句話

**武器表只寫「一般品質」的起點；一件裝備有多強，看它骰到幾個特殊效果（＝品質）、幾個孔、鑲了什麼珠子。**
全身所有來源的效果**等級相加**後查一次表；武器的基礎屬性是數值，效果用百分比／等級／加值去強化它。

## 1. 品質（稀有度）

| 值 | 色名 | 品名 | 特殊效果數 | 顏色（沿用 `RarityInfo`） |
|---|---|---|---|---|
| 1 | 白 | **一般** | 0 | `#DBD4C4` |
| 2 | 藍 | **良品** | 1 | `#669EEB` |
| 3 | 黃 | **珍品** | 2 | `#E0B852` |
| 4 | 紫 | **極品** | 3 | `#BD85ED` |

- 品名改了（原本「凡品／神品」）。**「神品」保留給未來新增的更高一階**，現在不用。
- 單一真相仍是 `RarityInfo`（`Scripts/Exchange/ExchangeData.cs`）；CSV 也接受 `一般`／`極品` 等新名稱，舊名照樣能解析。
- **裝備（武器／防具／珠寶）的品質＝這一件身上的特殊效果數量，不另外存，用算的**——永遠不會跟效果對不上。
- **非裝備物品**（藥水、珠子、血統藥劑、劇本…）的品質是**模板屬性**：ItemTable 新增 `Rarity` 欄，留空＝一般。目前全部一般；**之後新增道具時，AI 要先問作者稀有度**。
- 效果的**等級不影響品質**：穿透 lv1＋反彈 lv1＋散射 lv1 是極品，穿透 lv3＋反彈 lv3＋散射 lv2 也是極品。
- **孔數（0~6）跟品質無關**，各骰各的。

## 2. 部位與效果的分類

### 2.1 部位（用現有 `EquipSlot`，不加欄位）

| 類別 | EquipSlot | 能有的效果（生成時骰、鑲嵌時擋） |
|---|---|---|
| 武器 | Weapon | 只有**武器類**，且必須對這把武器的模式有效 |
| 防具 | Chest／Boots／Gloves | 只有**防具類** |
| 珠寶 | Amulet／Ring | **兩類都可以**（給玩家自由調配） |

### 2.2 效果分類（用 GemTable 現有 `Target`，不加欄位）

- `Recipe`／`Weapon` → **武器類**（目前 24 種都是）。
- `Player` → **防具類**（減傷、增防、法抗、增速…，**之後才規劃**；目前效果池是空的，所以防具生成時一律一般）。

### 2.3 有效性規則

| 情況 | 生成（骰內建效果） | 鑲嵌 |
|---|---|---|
| 武器 × 跨類別（防具類珠子） | 不會出 | **擋** |
| 武器 × 模式無效（例：佛光不吃反彈） | 不會出 | **擋** |
| 防具 × 武器類 | 不會出 | **擋** |
| 珠寶 × 武器類，但對**當下裝備的武器**無效 | 照常可出（珠寶沒有模式） | **不擋**，灰顯＋tip 說明（現行行為） |
| 廣角（要先有分裂才有作用） | 這一件已有分裂（起點或已骰到）才可能骰到 | **不擋、只提示**（可能靠戒指上的分裂生效） |

- 模式有效性沿用 `WeaponModeSpec.IsEffective`（「模式 × 欄位」自動推導，新配方不用回頭填表；只有新增模式時要宣告用到哪些欄位）。
- 另加一張**例外表**（可空）：寫「技術上有效、但設計上不想讓它出現」的「效果 × 模式」組合。

## 3. 基礎屬性（填數值，是武器的本質）

每把武器都有、決定強弱與手感的六個屬性。**直接填數值**，不靠等級撐；前中後期的強度差交給新武器的基礎值。

| 基礎屬性 | 依模式對應的欄位 | 強化它的效果（百分比） |
|---|---|---|
| 傷害 | `Damage` | 銳利 |
| 攻擊頻率 | 單發型：`FireInterval`／雷射：`DotInterval`／佛光：GroundEffectTable 的 `DamageInterval` | 疾發 |
| 飛行速度 | `Speed`（只有投射物；拋物線換算成縮短 `FlightTime`） | 迅捷 |
| 射程 | 子彈：`LifeTime`（環繞＝整組持續時間）／雷射、連鎖、施放、迴旋、掃射、投彈：`Range`／浮游：兩者一起 | 遠射 |
| 大小／範圍 | `BulletScale`／雷射、連鎖：`BeamWidth`／落雷：兩者一起 | 須彌 |
| 耗魔 | `ManaCost` | 省魔 |

**模式參數**（環繞數量、環繞半徑、召喚數、連鎖跳數、突進距離、扇形角度…）也填數值，但只屬於特定模式，不算通用基礎屬性。

## 4. 特殊效果（24 種，三種算法）

### 4.1 三種算法

| 算法 | 適用 | 起點怎麼填 | 最終值 |
|---|---|---|---|
| **百分比** | 強化基礎屬性與模式參數 | 數值（基礎屬性本身） | `基礎 × (1 + 全身百分比總和)`；**越小越好的屬性用除法**：`基礎 ÷ (1 + 總和)` |
| **純等級** | 行為（有或沒有） | **等級**（留空＝沒有這個能力） | `查表(起點等級 + 全身效果等級)` |
| **加值** | 模式參數的數量／角度 | 數值 | `起點 + 查表(全身效果等級)` |

- **全身等級相加**：武器起點、武器內建效果、各部位內建效果、所有鑲嵌珠，同一種效果的等級全部加總，再查一次表。
  例：枯枝起點穿透 lv1＋內建穿透 lv2＋戒指穿透珠 lv1 → 穿透 lv4。
- **單一來源 lv1~3**：一顆珠子、一條內建效果最高 lv3（珠子之後靠強化石升級）。起點等級不受此限。
- **總等級封頂 50**（各效果另有 `MaxLv`，超過照封頂值）。作者：「不希望玩家真的到這數字」——效能極限（子彈乘積等）放到體系完成後做極限測試再處理。
- **越小越好的屬性一律用除法**（攻擊間隔、耗魔、集氣時間）：攻速 +250%＝間隔 ÷ 3.5。用減法會在 100% 時歸零讓遊戲當掉，除法永遠不會。

### 4.3 分裂的角度（取代原本的「扇形總角度」）

照「平行」現成的作法（間距＋總寬上限、超過就壓縮）：

- 新欄 `SpreadSpacing`（每顆間距，度）＋`SpreadMaxAngle`（扇形上限）。留空的預設：間距 15°、上限 90°。
- 總角度＝`min((N−1) × 間距, 上限) ＋ 廣角加值`，超過上限就壓縮間距；廣角**直接加在總角度上**（實作時修正：只放寬上限的話，沒被上限卡住的武器鑲廣角會沒感覺）。
- 公式在 `RecipeEntry.ComputeSpreadAngle`（讀表與能力容器共用）。沒有扇形欄的模式（頭頂投彈）維持 0。
- 到 360° 時改成平均分一整圈（每顆間隔 360/N），首尾不重疊（現在山崩地裂、夏綠蒂填 315° 就是在繞這個問題）。
- 原本的 `SpreadAngle` 欄遷移成上限後**移除**。

## 5. 一件裝備的資料（實例）

`ItemInstance` 新增：

```
affixes: [ { effectId: 2, level: 2 }, { effectId: 1, level: 1 } ]   // 內建特殊效果（穿透 Lv2＋反彈 Lv1），最多 3 條、不重複
```

- `effectId` ＝ **GemTable 的 GemID**（不是珠子的物品 ID），跟規格語法 `fx=` 用同一套編號。

- 品質＝`affixes.Count`（0~3），不存。
- 舊存檔缺這個欄位＝空＝一般，不用遷移。
- 同一件裝備**不能有兩條同種效果**；但**起點不算效果**，所以「起點穿透 lv1」的枯枝仍可能骰到穿透。

## 6. 生成規格（給道具時寫死或動態骰）

所有「憑空給一件物品」的路徑仍然只走 `ItemManager`（唯一工廠）；工廠多吃一份**規格**。

### 6.1 規格語法（所有來源共用同一個解析器）

接在 itemId 後面的中括號，欄位用 `;` 分隔，**全部選填**：

| 鍵 | 意思 | 例 |
|---|---|---|
| `q` | 寫死品質 1~4 | `q=4` |
| `s` | 寫死孔數 0~6 | `s=1` |
| `fx` | 寫死效果：`效果ID@等級`，多條用 `\|`（效果 ID＝GemTable 的 GemID，見 §4.2） | `fx=2@2\|1@1`（穿透 lv2＋反彈 lv1） |
| `lv` | 寫死珠子等級 1~3（只對能力珠有意義） | `lv=1` |

| 寫法 | 意思 |
|---|---|
| （不寫） | **全隨機**：品質、效果、孔數都骰 |
| `[q=3]` | **寫死品質、效果隨機**：骰 2 個效果，孔數骰 |
| `[fx=2@2\|1@1]` | **全寫死效果**：品質由效果數決定（這裡＝珍品） |
| `[q=1;s=1]` | 一般、1 孔 |

### 6.2 動態骰的流程

1. 品質：寫死就用寫死的；沒寫死照 `RandomRules` 權重骰（⏳ 先放佔位，平衡時再調）。
2. 從**對這件物品有效**的效果池（§2）挑 N 個**不重複**的效果，各自骰 lv1~3（權重在 `RandomRules`）。
3. 有效效果不夠 N 個 → 自動降一級。**寫死品質卻達不到的**（例：某武器能吃的效果太少），載入表格時就印警告，上架前就抓到。
4. 孔數：寫死就用；沒寫死照現行 `RandomRules` 骰 0~6、隨機開位置。

### 6.3 各來源怎麼填

| 來源 | 寫在哪 |
|---|---|
| 兌換所 | `ExchangeTable.csv` 新欄 `Spec`；原 `Rarity` 欄**移除**（裝備品質看 Spec、非裝備看 ItemTable） |
| 怪物掉落 | `DropTable.csv` 槽位：`itemId:機率%:數量[規格]`，例 `10003:100:1[q=3]` |
| 劇本 `giveItem`、拾取點 `pickup` | 新參數 `spec`；**地圖編輯器加輸入欄** |
| 祭壇抽選 | 不填＝全隨機（作者定：抽選從四種品質隨機給） |
| 作弊面板 | 可填規格，方便測試 |

## 7. 顯示

- **名稱**：裝備＝`品名 名稱`、整串用品質色（例：<span style="color:#669EEB">良品 兒童彈弓</span>）。非裝備只上色、**不加字樣**。
- **外框**：道具格框、tip 外框用品質色（細框，遵守 UI 規範「稀有度色不大面積鋪色」）。
  - 道具格框**只畫良品以上的裝備**（一般不畫，免得背包每件裝備都一圈白框）；要全部都畫改 `ItemQuality.FrameMinRarity` 一個常數。tip 外框一律畫。
- **tip 分三區**：
  1. 基礎屬性（含起點的行為，例：枯枝的「穿透 Lv1」）
  2. 特殊能力（品質色，一行一條，例：「反彈 Lv2」）
  3. 鑲嵌孔
  - 數值顯示**這一件自己的**（基礎＋這一件的效果＋這一件的珠子），不含其他部位。
- 套用到：背包、倉庫、鍛造、地上掉落標籤、結算畫面、兌換所、抽選。
- **兌換所**：裝備一律寫死極品，所以列表顯示紫色「極品 XXX」；效果與孔數在兌換那一刻才骰。
- **抽選**：改成**先骰好再表演**，單抽與十連的表演和結算都顯示實際拿到的那一件（含品質）。順帶修掉「抽選面板顯示珠子等級固定 Lv1」的舊缺口。

## 8. 數值尺度 ×10

傷害與血量全遊戲一起放大 10 倍，讓百分比加成看得到（傷害 1 加 5% 是 1.05，畫面上看不出來）。

| 一起 ×10 | 不動 |
|---|---|
| WeaponTable `Damage`、`ManaCost`（玩家、怪物、同伴、子武器、被動武器全部） | 百分比類：血球回最大血魔 20%、`DamageReduction`（減傷 %）、GM 武器的「扣最大血量 10%」 |
| MonsterData `HP`、`ContactDamage`、`LeapDamage`、`BombDamage` | 倍率類：集氣 ×3、陣營演戲 1/100、牢籠崩裂倍率、自爆／跳砸留空時「接觸傷害 × N」 |
| NpcTable `HP`、GroundEffectTable `Damage`（子彈命中放的地面特效、落雷留痕會用表上的值） | 貨幣（功德值、證明）、價格 |
| ItemTable `HealHp`、`HealMp`（藥水回復量） | |
| 玩家（`Player.prefab`）：最大血 100→1000、最大魔 50→500、回魔 5→50／秒 | |
| **CSV 留空時的程式預設值**：武器傷害與耗魔 1→10、接觸傷害 10→100、NPC 血量 50→500 | |
| **程式寫死的數字**：榕樹妖地刺 10→100、巨木 30→300、劇本同伴 1→10、`Monster.prefab` 預設血量 50→500 | |
| **可破壞地上物血量**：三份地圖檔（編輯器 `Maps/`、`GameAssets`、`StreamingAssets`）的正數 `hp` ×10（-1＝不可破壞不動）、編輯器與遊戲端缺省 1→10、`MapLoader.objectMaxHP` 20→200 | |

## 9. 配方表欄位變動與舊武器遷移

### 9.1 欄位變動

| 舊欄 | 新欄 | 填法 |
|---|---|---|
| `PierceCount` | `PierceLv` | 等級 |
| `MaxBounces` | `BounceLv` | 等級（`HasBounce`／`BounceTarget` 連動照舊） |

| `SpreadAngle` | `SpreadSpacing`＋`SpreadMaxAngle` | 數值（§4.3） |
| 其他 | 不變 | 數值 |

- **欄名直接表示填法**，以後自己填不會誤會。

- **武器工坊**同步：顯示新欄，等級旁邊顯示換算後的實際數值。
- 無限穿透（-1）取消：新武器一律填有限等級；舊的 -1 遷移成 lv50。
- `LifeTime`／`Range` 的 -1（不消失／無限長）是基礎屬性的本質，保留；射程珠對它們無效。
