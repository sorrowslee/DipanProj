## 0. 這是什麼、為什麼要這樣做

《燃燈劫》的玩法有一大塊是「劇本」（關卡事件編排）。紅嫁衣劇本由作者獨力完成；血狂之爭做到一半後進度停滯，原因是**劇本工作一直沒有被拆成能交給 AI 的形狀**：缺功能（程式）、編排邏輯（資料）、空間擺放（要看畫面）三種性質的工作綁在一起，任何一種卡住整條線就停。

這批文件把血狂之爭拆開：

| 性質 | 例子 | 誰做 |
|---|---|---|
| **缺功能**（程式） | 二選一倒數面板、編輯器多段演出、兩隻頭目 | AI，完全交出去，作者驗收 |
| **編排邏輯**（`.dipanmap` JSON 資料） | 哪顆 trigger 接哪顆、傳送點何時封、哪一波刷什麼怪、旗標叫什麼 | AI 寫，作者審 |
| **空間擺放**（要看畫面） | 出生點塗哪幾格、NPC 站哪 | AI 先依可走層估一個位置塗好，**作者在編輯器微調** |

**同時這也是一次能力測試**：作者要看 AI 在劇本編排上能做到什麼程度，結果會決定之後劇本量產的工作方式。所以——**做得到的要做好，做不到的要講清楚為什麼**，不要硬湊一個看起來完整但沒驗證的東西（DOCS_GUIDE 第三節：沒查證過的不要寫）。

## 1. 接手 AI 的工作方式（主管交辦）

### 1.1 開工前

1. 讀根目錄 `AGENTS.md`（常駐鐵則、路由表）——**全文**。
2. 讀本資料夾四份文件——**全文**。
3. 依 [TASKS.md](TASKS.md) 每張任務單列的「先讀」清單，讀指定文件的**指定章節**（不必整份）。
4. 讀完後**先向作者回報一段話**：你打算先做哪張任務單、預計動哪些檔、有哪些待確認事項（§4）要作者先拍板。**得到回覆再動手。**

### 1.2 動工中的鐵則（本任務專屬，疊加在 AGENTS.md 之上）

- **只動血狂之爭的東西**：`DipanProj_MapEditor/Maps/BloodFang/*.dipanmap`、各 CSV 的**新增列**、`flags.json` 的**新增旗標**、以及 T2／T2b／T8 任務單明確列出的程式檔。**不動其他 module 的地圖、不動既有 CSV 列的既有欄位**（T1 列出的幾個 Faction 欄例外）。
- **擴大範圍前先問**：發現「要做好這件事得順手改 X」時，即使方向正確，也先停下來問作者，不要自己決定。
- **git 完全由作者掌控**：不 commit、不切分支、不 push。唯讀查詢一律 `git --no-optional-locks ...`（PROBLEMS **I9**）。目前工作分支是 `docs/bloodfang-script-plan`（本批文件就在上面）；作者會自己決定要不要再開分支。
- **直接編 `.dipanmap` JSON 的規矩**（這是本任務最大的新做法，見 §2）。
- **一次做完一個 Slice 再回報**，不要做一半就拋回來；但每個 Slice 之間**一定要回報、等作者實測後才做下一個**——這個專案很多系統（陣營、偵測條件、血蝠、血術士）都是「程式完成、未實機驗證」，實測結果會改變下一步的做法。
- **做完記錄三件套**（PROGRESS／PROBLEMS／TODO，格式見 `readme/DOCS_GUIDE.md`）＋把本資料夾的狀態列更新。
- 沒有 C# 編譯器可用：改程式後跑 PROBLEMS **I10** 那套「用到但沒宣告」檢查；改 JSON 後一定 `python3 -c "import json;json.load(open(...))"` 驗一次。

### 1.3 跟作者溝通的格式

每個 Slice 完成時回報固定四段：

1. **做了什麼**：動了哪些檔、新增哪些 trigger／旗標／對話（表格）。
2. **請作者做什麼**：編輯器開哪張圖看什麼、哪些位置要微調（逐條列，附格子座標）、要不要 Sync、怎麼進關測（`Project Tools → 測試 → 直接進關卡 → 血狂之爭 (BloodFang)`）。
3. **預期看到什麼**：一條一條的驗收清單（作者照著打勾／回報症狀）。
4. **我不確定的**：哪裡是估的、哪裡可能壞、壞了優先懷疑什麼。

跟作者提 Unity Inspector 欄位給英文標籤；提地圖編輯器面板欄位給中文標籤（編輯器是中文 IMGUI）。

## 2. 直接編 `.dipanmap`：AI 怎麼接手「編排」工作

`.dipanmap` 是純 JSON（Newtonsoft 序列化），編輯器與遊戲都讀它。觸發點住在 `layers[]` 裡 `type=="Trigger"` 那層的 `regions[]`，NPC 住在頂層 `npcs[]`，劇情演出住在頂層 `cutscenes[]`。格式細節見 `readme/MapEditor_DESIGN.md`；**最可靠的範本是現成的地圖**——紅嫁衣 `RedBridalGown_BridalRoom.dipanmap` 的 trigger 層有一整套 boss 房接法（drama → bossIntro → togglePortal → 出生點 deathFlag → watchFlag → 對話 → clearLevel），**先讀它再寫自己的**。

### 2.1 寫 JSON 的規矩

| 項目 | 規矩 |
|---|---|
| region `id` | 8 位小寫 hex（如 `db75a639`），同圖不重複。用 `python3 -c "import secrets;print(secrets.token_hex(4))"` 產 |
| region `name` | **全中文、同圖不重名**，照既有慣例「類型-說明」（如 `傳送點-南方`、`怪物出生點-血蝠`）。鏈的 `next` 用名字對接，所以名字就是 API |
| `typeId` | 只用 `DipanProj_MapEditor/Assets/StreamingAssets/triggerTypes.json` 裡有的型別 |
| `params` | **值一律字串**（`"20"`、`"1.6"`），布林用 JSON `true/false`（現有檔如此）。留空的欄位可以不寫（舊地圖缺欄＝預設） |
| 通用欄位 | `next`／`setFlag`／`requireFlag`／`startDisabled`／`enableFlag`／`repeat`／`onBlocked`／`conditions` 等**也放在 `params` 裡**（見紅嫁衣範本） |
| `cells` | `[[x,y],...]`，**格座標**；動作型 trigger 畫 0 格（`[]`）或角落 1 格；位置型（出生點、camZone、踩點 drama）要塗在**可走格**上（§2.2） |
| 旗標 | 地圖裡只存裸名（`bfWarStarted`）或否定（`!bfWarStarted`）；生命週期在 `flags.json` 登記（§2.3） |
| NPC | 照 `npcs[]` 既有物件的欄位全列（`conditions` 字串格式見 TRIGGER_CHAIN §2.6） |
| 寫回 | `json.dump(..., ensure_ascii=False, indent=2)`；改完 **re-load 驗證**；不要重排既有欄位順序以外的東西，diff 要乾淨 |

### 2.2 位置怎麼估

`layers[]` 裡 `type=="Walkable"` 那層的 `blocked` 是 `height×walkSubdiv` 列字串、每列 `width×walkSubdiv` 字元（本模組 `walkSubdiv=4`，所以一格＝4×4 子格），`'0'` 可走／`'1'` 牆／`'2'` 水。**一格 16 個子格全 `'0'` 才算安全可走格。** 用這個算出每張圖的可走區，再決定：

- 出生點：塗在離入口傳送點 ≥4 格、離玩家落點 ≥3 格的可走格，一格一隻。
- camZone／踩點：入口傳送點 `markerX/markerY`（世界座標；y 軸向下為負，格 y＝`-markerY` 取整）附近 3×3。
- 回報時**把估的位置列成表**，讓作者在編輯器一眼能找到並微調。

### 2.3 旗標登記

`DipanProj_MapEditor/flags.json` 是編輯器旗標管理器的存檔，格式見現有內容（`id` 接最大號、`name`、`scope`＝`cycle|life|level`、`IsLife`/`IsLevel`/`ScopeLabel` 跟著 scope 一致）。本劇本所有旗標**一律 `level`（關卡單次）**（見 SCRIPT §5）。改完要作者跑一次 `Project Tools → Sync Map Assets` 才會進遊戲（PROBLEMS **I4**）。

### 2.4 作者這邊的循環

AI 寫 JSON → 作者開地圖編輯器打開那張圖（檢查有沒有報錯、看位置）→ 微調 → 存檔 → `Sync Map Assets` → 測試選單進關 → 回報。**作者存檔會重寫整個 JSON**，所以 AI 下一輪動工前**一定重讀檔案**，不要用上一輪的記憶。

## 3. 範圍：這一批做到哪

- ✅ 依玩家血統分三種走法（SCRIPT §1）：血族／狂族玩家由自己族的接待員引路、和談後**直接入自己族**、只走自己那條；非血狂族由管家引路、才有二選一與隱藏線。全部編排到「從大門離開、進結算」。
- ✅ 新功能三個：**二選一倒數面板** `timedChoice`（GAP §2）、**編輯器多段演出**（GAP §8）、**兩隻頭目 Brain**（GAP §9，AI 設計，含 AI 自繪序列圖一版）。
- ✅ NPC 引路用劇情演出（Cutscene）做；跟隨型 NPC 仍不做。
- ❌ 不在本批：劇本道具（ItemTable 新列、邪佛發牌）、過關獎勵內容、首領產圖素材、正式平衡數值。記進 TODO。
