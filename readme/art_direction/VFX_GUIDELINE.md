# 場景特效製作準則 (VFX Guideline)

## 1. 風格語言：特效是「畫出來的」，不是「渲染出來的」

1. **手繪色塊優先**：特效由 2~4 個明確色階的色塊構成（亮核心／主色／暗邊），
   有可辨識的輪廓形狀；避免「純高斯光暈＋粒子噴發」的引擎渲染感。
   參考語彙：《魔女庭園》斬擊的色塊＋黑色負形撕裂邊；本專案水墨泡泡的滲透邊。
2. **黑色負形是我們的武器**：在特效內部或邊緣摻入深色的撕裂／墨漬形狀，
   立刻擺脫 glow 感，而且跟中式水墨題材天然相容。
3. **買來的特效包是原料不是素材**：進遊戲前必過兩道工序——
   ①（必要時）改色以服從場景強調色（特效預覽器有換色功能，見 [EFFECT_LIBRARY.md](../EFFECT_LIBRARY.md)）；
   ② 確認質感跟已在遊戲內的特效同語言，突兀的寧可不用。
4. **程式生成的佔位素材**（花椰菜煙塊、柔光圓）可以先動起來，但要在 TODO 記「待替換成手繪語言素材」，
   不讓佔位變永久。

## 2. 色彩紀律

1. **特效色服從場景強調色**（總綱紀律一）：做/挑特效時先問「這是進哪張圖的」。
   同一顆武器特效跨多圖使用時，以「全遊戲通用色」處理——低飽和基底＋小面積高飽和核心，
   到任何色調的場景都不打架。
2. **同框特效色系 ≤ 2~3 種**。新特效上線前，在它最常出現的場景實機截圖數一次。
3. **特效屬於明度階層第 4 層**（全畫面最亮），但「亮」集中在小面積核心；
   大面積的部分（煙、霧、範圍圈）要低飽和低 alpha，別做成一大片高亮色板。
4. **暗部不用純黑、亮部慎用純白**：往場景主色偏的深色/亮色。

## 3. 發光與疊層（血淚區，全部有編號可查）

1. **比較兩個加色層的強弱，算整串 `貼圖alpha × color.a × _Intensity`**，別只看 `_Intensity`
   （[PROBLEMS](../PROBLEMS.md) **E12**；量 PNG 平均 alpha 用小工具最快）。
2. **兩個發光層疊同位置是零和**——要同時可辨識，讓一層改走「暗色剪影吃光」，
   且剪影 sortingOrder 要在光之上（**E13**；加色永遠做不出不透明）。
3. **加色的冷色疊在暖光池上會偏粉/偏白**：紅通道先壓低再進場（**E12** 順帶 1）。
4. **估疊色參數一律拿實機截圖量 RGB**，不要用自己合成的暗底圖調（**E12** 順帶 2）。
5. 專案是 **Linear 色彩空間**：alpha 憑直覺填會重一倍，公式驗證法見 **E11**。
6. 動佛光／照明範圍前必讀 [FALLEN_BUDDHA_LIGHT.md](../FALLEN_BUDDHA_LIGHT.md)。

## 4. 定位、排序、生命週期（技術紀律）

1. **定位**：掛在角色身上的特效用 `FeetWorldPos` / `BodyCenterWorldPos` / `VisibleBodyHeight`、
   出手點用 `MuzzleWorldPos`；**禁止** `transform.position` 當身體中心、`SpriteRenderer.bounds` 當可見範圍
   （**E14**；體型可變之後這些假設全破）。撐過體型變更的持續特效記得掛進
   `PlayerController.RefreshBodyScaledVisuals()`。
2. **排序帶是資源，先查表再選號**：`MapDepthSort.cs` 檔頭配置表是唯一真相；
   世界帶 1000~18999、表演層 20000 起、sortingOrder 實質 16-bit（**E4／E15**）。
   新特效落點先想清楚「要被地上物遮（進世界帶、走 Y 排序）還是永遠在上（表演層）」。
3. **`Duration=-1` 的循環特效一定要有明確的 Destroy 負責人**（VFX.md 的 id 31 教訓）。
4. **VfxTable 的 `AniNumber` 必須與實際張數完全相符**——差一張整個特效直接不顯示（全有或全無）。
5. 暫停中要播的演出記得 `Unscaled = true`（PROBLEMS **D15**）。

## 5. 暗場景成立性（必要驗收）

每個新特效在**最暗的目標場景**（Atmosphere 2 幽暗／3 噩夢／9 深海恐怖）實機看一次：

- 加色/提亮類在暗場景天然醒目——反而要驗「會不會太亮、搶過角色」。
- 依賴底色的（半透明染色、乘法類）在暗場景會安靜失效（**J4** 的姊妹題）。
- 同時驗最亮場景（Atmosphere 1／4 烈日）：柔光類在亮底上容易消失。

## 6. 氛圍粒子（總綱紀律六的執行）

1. 每張地圖至少一種低成本環境粒子：飄灰、香灰、螢火、落葉、花瓣、塵埃光斑。
   實作走 SceneFxTable **加列不加程式**（stream kind、低 EmitPerSecond、低 PeakAlpha、長壽命）。
2. 氛圍粒子是**背景不是焦點**：低密度、低 alpha、色相跟著場景主色；
   玩家「感覺畫面是活的」但說不出有粒子＝調對了。
3. 光源會呼吸勝過恆定亮度——照明的搖晃參數（各盞獨立相位）已內建，擺燈時別全設 0。

## 7. 上線前自檢清單

- [ ] 這個特效進哪張圖？色彩服從該圖強調色了嗎？
- [ ] 質感跟現有特效同語言嗎（手繪色塊感、非裸 glow）？
- [ ] 疊層算過整串等效亮度嗎？有沒有跟既有發光層在同位置爭亮度？
- [ ] sortingOrder 查過 MapDepthSort 配置表了嗎？
- [ ] 定位走的是可見身體幾何（不是 transform / bounds）嗎？
- [ ] 最暗與最亮的目標場景都實機看過了嗎？
- [ ] 循環特效的 Destroy 有負責人嗎？AniNumber 對過張數嗎？
