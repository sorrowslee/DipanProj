## 1. 職責升級：Atmosphere 是「統一調色」，不只是「加效果」

每個 Atmosphere mode 的本職是替那張地圖執行色彩劇本。**一個 mode 要能用三句話說完**：

1. **主色調染色**：陰影/中間調往地圖主色偏（例：鬼霧 14 的陰綠、焦土 5 的暗橙紅）。
2. **明度塑形**：整體壓暗程度＋暈影（vignette）——把「地面最暗、四角更暗、玩家在光池」
   的階層鎖進後處理，讓漏網的過亮素材也被「染進」場景。
3. **動態元素**：最多一種招牌動態（風絲／雨絲／黑霧／熱浪…），低調常駐。

說不出這三句＝這個 mode 還沒設計完。新 mode 或改現有 mode 時，順手檢查
「降飽和」有沒有做——去飽和是把雜色素材統一進場景的最便宜手段（type 2/3 已有，其餘視主色需要）。

## 2. 設計規則

1. **暗場景成立性是必要驗收**（[PROBLEMS](../PROBLEMS.md) **J4** 通則）：
   乘法/壓暗/模糊類效果需要畫面本來有亮度，在 Atmosphere 2/3/9 上會**安靜失效**；
   要在暗場景可靠被看見，用**加法**（提亮、白霧、發光）或**幾何**（黑邊、遮罩、輪廓）。
   任何新螢幕效果先想清楚它會被套在哪幾種 Atmosphere 上、最暗那種還成不成立。
2. **Linear 色彩空間**（**E11**）：alpha 憑 Gamma 直覺填會重約一倍；
   調疊色先用 `a*C^2.2+(1-a)*BG^2.2` 開 1/2.2 次方驗算，或直接實機截圖量 RGB 對答案。
   優先用明暗對比與描邊，避免大面積半透明。
   **同一個坑的另一半：shader 裡的每個「亮度門檻」也是 Linear 值**——Linear 專案裡「看起來一半亮」
   實際只有 0.08 上下，憑直覺填 0.5 的門檻永遠不觸發，而症狀是「效果好像沒做」不是報錯（**E26**）。
   定門檻前先量一張該場景截圖的 linear percentile（E26 附程式碼），門檻要落在 p25~p90 之間。
3. **動態要「呼吸」，不要「閃爍」**：
   - 週期用 Perlin／多相位 sin 疊加，避免單一 sin 的機械感；
   - **多實例各自獨立相位種子**（照明多光源的教訓：整排火把同步明滅一眼假）；
   - 幅度寧小勿大——玩家「感覺場景是活的」但說不出哪裡在動＝調對了。
4. **模糊的 tap 數跟半徑成比例**（**J5**）：半徑加大取樣不加＝重影馬賽克；
   驗收看最大半徑處的一個硬邊物件。全屏「邊緣處理」先問「演出會不會用到邊緣」
   （J5 後續：邊緣模糊跟 NPC 走位本質衝突而關閉）。
5. **強調色保護**：後處理統一調色的同時，不能把場景的強調色物件（佛光、霓虹、關鍵特效）
   染到失去身分——調完在有強調色物件的實機畫面上驗一次。

## 3. 技術紀律

1. **鏡像與雙處常數要同步改**：`MaxLights`(20，2026-08-28 由 12 提高) ↔ shader `MAX_LIGHTS`；
   編輯器 `LightPreview`／`EditorLightPreview.shader` 與遊戲端 type 1 分支同一條式子；
   同框光源上限寫死在兩處（AGENTS 鐵則同款）。
2. **Bypass 相容**：任何新 mode／新效果必須被 `AtmosphereController.SetBypass` 統一淡掉——
   效果寫在 `Atmosphere.shader` 最後一行內插**之前**。「暫時脫離當前場景」的演出一律走 SetBypass，
   不要自己另疊一套反向補償。
3. **效能**：動態一律 `_Time` 驅動的 hash/sin 程序噪聲（無貼圖、無額外 pass）；
   新效果維持單 pass Blit；加第二張全屏貼圖或多 pass 前先量 PerfHud（P 鍵）。
4. **UI 與互動指引不受後處理影響**：HUD 是 Screen Space Overlay、互動星星在 InteractOverlay
   疊加相機——新效果不得改變這個約定（玩家指引永遠可見）。
5. **資料驅動**：新氛圍＝MapsTable `Atmosphere` 欄新值＋shader `_Mode` 分支；
   留空/缺欄必須等於「無效果」，舊地圖零影響（EnvBright 缺欄=100 同款防呆）。

## 4. 全屏質感層規格（總綱紀律五，待實作時照此）

1. **材質**：宣紙紋／水墨滲透紋優先（貼題材、與水墨泡泡同語彙）；印刷網點為備選。
2. **強度**：目標是「截圖有質感」而非「看得見一層紋理」——從等效 alpha 3~5% 起手
   （記得 E11：Linear 下直覺值減半），實機截圖放大驗。
3. **實作位置**：Atmosphere 管線內的常駐 overlay，所有 mode 共用、受 SetBypass 統一控制；
   與 type 15 電視雜訊同框時只留一種質感（雜訊 mode 自帶質感，疊加會髒）。
4. **紋理來源**：程序噪聲優先；若需貼圖，單張灰階、可平鋪、解析度夠（參考 PortalFx 提解析度的前例）。

## 5. 新 mode／新螢幕效果 checklist

- [ ] 三句話說得出：主色調染色／明度塑形／動態元素？
- [ ] 有降飽和的考量（要或不要，說得出理由）？
- [ ] 最暗（2/3/9）與最亮（1/4）場景都實機驗過？
- [ ] alpha 用 E11 公式或實機量色驗過？
- [ ] 動態多相位、多實例獨立種子、幅度克制？
- [ ] SetBypass 淡得掉？UI/星星不受影響？
- [ ] MapsTable 留空＝無效果、舊圖零影響？
- [ ] 兩處寫死的常數、編輯器鏡像同步了？
- [ ] PerfHud 量過幀數；截圖過總綱附錄 B 自檢表？
