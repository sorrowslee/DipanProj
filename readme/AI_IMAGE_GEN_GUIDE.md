# AI 產圖流程指南 (AI Image Generation Guide)

> **給未來的 AI / Cowork：** 本專案要產任何圖片素材時，**先讀完這份文件再動手**。
> 這份文件記錄了實際跑過一輪後驗證可行的流程、踩過的坑、以及各種注意事項。
> 通用流程對「任何圖」都適用；最後一節「飛行道具專屬」只有在產**會飛出去的投射道具**時才需要額外遵守。

## 1. 前置條件（沒做到就無法產圖）

1. **Chrome 擴充功能必須已連線。** 用 `list_connected_browsers` 檢查，回傳空陣列代表沒連上。
   使用者需：桌面 App 設定開啟 Chrome connector → 擴充功能用同帳號登入 → **完整重啟 Chrome** → 授權控制分頁。
2. **使用者需登入 Scenario。** 操作的分頁要在已登入狀態（cookie 共用，新開分頁也會是登入狀態）。
3. **「下載」資料夾要已授權給 Cowork。** 這是整條流程的關鍵（見第 3 節原因）。
   若沒授權，用 `request_cowork_directory` 請使用者掛載 `~/Downloads`。

## 2. 基本產圖流程（適用任何圖）

1. 確認分頁在產圖頁（上面的網址）。若不在，用 `navigate` 導過去並等載入。
2. 點提示詞輸入框 → （若有舊內容）`cmd+a` 全選 → `Delete` 清空 → 輸入新提示詞。
3. 點 **Generate**（左下角藍色按鈕）送出。Seedream 約需 **15–25 秒**出圖。
4. 出圖後在右側 Session 網格最新位置（通常左上第一格）會出現結果。
5. 點該圖開啟細節檢視 → 點右上角**下載圖示** → 選 **PNG** → 圖會下載到使用者的「下載」資料夾。
6. 用 bash 從「下載」資料夾把檔案搬進 `TempImage/`，並改成有意義的檔名。
7. 視需要做去背（見第 4 節）。

## 3. 重要踩雷紀錄（務必避開）

- **不能把圖片位元組「讀進對話」再寫檔。** 瀏覽器工具會**封鎖 base64 資料回傳**（防資料外流），
  用 `javascript_tool` 把圖轉 base64 回傳會得到 `[BLOCKED: Base64 encoded data]`。
- **不能用 bash 的 curl / wget 抓圖片網址。** 安全規範禁止，這條路不要嘗試。
- **結論：取得圖檔的唯一可行路徑＝用 Scenario 的原生下載鈕，讓檔案落到已掛載的「下載」資料夾，再用 bash 搬移。** 所以第 1 節的「下載資料夾授權」是必要前置。
- **左上角 (28,23) 那個圖示是「首頁 Logo」不是關閉鈕。** 誤點會跳回 Home，要用 `Escape` 或正確的關閉鈕（細節頁左上角的 X）關閉檢視。
- **下載選單偶爾第一次點不開**，沒看到 PNG/JPEG/WebP 選單就再點一次下載圖示，並截圖確認選單有開再點 PNG。
- **產出的圖多半是「實底」不是真透明。** 檢視器會顯示透明棋盤格容易誤導，但下載下來常是 RGB 灰底/白底/深底。要透明就得自己去背（第 4 節）。本專案現有 sprite 是 RGBA 透明，所以通常需要去背。
- **bash 無法硬刪掛載資料夾裡的檔案**（權限限制）。中間檔（RAW 等）若要清，請使用者手動刪，或一開始就不要留中間檔。
- **同一對話連續產很多張，成本會越疊越高**（每一步都會重讀整段對話）。量產請**分小批**或**開新對話**重置上下文。
- **🚫 絕對不要用 JS 程式化下載（`a.click()` 觸發 blob 下載）。** 它沒有使用者手勢，Chrome 會靜默封鎖，而且會連帶把該分頁的「自動下載多檔」權限鎖死，導致之後連原生下載鈕都失效。
- **⚠️ Chrome「自動下載多檔」封鎖：** 同一分頁累積下載到第 3–4 個，Chrome 會跳出封鎖（解除圖示在網址列，AI 點不到）。之後該分頁所有下載都會無聲失敗。
  - **根治法（建議，一次性）：** 到 `chrome://settings/content/automaticDownloads`，把 `https://app.scenario.com` 加入「允許」清單。之後量產不再被擋。
  - **臨時繞法：** 每下載約 3 張就用 `tabs_create_mcp` 開新分頁、重新導到產圖頁繼續（新分頁的下載計數會重置）。
- **每次下載後務必用 bash 確認檔案真的落地**（依 asset id 比對），失敗就重試，不要盲目接著產下一張（會連環跑錯，例如誤觸 Enhance 跳到 /enhance 頁）。
- **下載選單是 toggle，且圖未載入完成時點不開。** 開細節頁後等圖**完全載入（約 5–10 秒）**再點下載鈕，並截圖確認 PNG/JPEG/WebP 選單有開再點 PNG。

## 4. 去背方式（兩種，預設用本地）

### 4-1. 本地去背（預設、推薦）
- 用程式從圖片四邊做 flood-fill，把與背景同色的區域 alpha 設 0。
- **優點**：免費、全 2048 解析度、不耗額外瀏覽器步驟（token 最省）、無次數限制。
- **適用**：背景乾淨單一色（純底）的圖 —— 只要產圖時提示詞指定純底，本地去背就很乾淨。
- **注意**：它只把透明像素 alpha 設 0、RGB 灰值會留著（遊戲引擎吃 alpha 不受影響，但預覽可能看到殘留灰）。邊緣的抗鋸齒像素去背品質取決於背景對比。
- 參考腳本邏輯：四邊入佇列 BFS，`isbg` 判斷「與四角平均色的歐氏距離 < 容差(約50) 且低飽和度(<35)」就設透明並擴散。這樣可同時處理**淺底/中灰底/深底**等任意均勻背景（純用亮度門檻會漏掉中灰底）。
- 提示詞固定指定 `plain flat grey background` 可讓背景夠均勻，本地去背最穩。

### 4-2. remove.bg（備案，背景複雜時用）
- 網站：https://www.remove.bg/zh/upload
- **免費版下載限 500×500**（最大 2048 要付費解鎖）；AI 邊緣較乾淨無灰邊。
- 操作關鍵：上傳框的 `<input type=file>` 是**點「上傳圖片」後才動態生成**的。
  做法：先點上傳鈕生成 input → 用 `javascript_tool` 把它顯示出來 → `find` 取得 ref → 用 `file_upload` 直接塞檔（**不要**用點擊，會開系統檔案視窗無法操作）。
- 處理完點「下載」→ 選免費的「預覽 500×500」。

## 5. Token 成本參考（估算）

主要成本是「截圖」，每張全頁截圖約 1,500–1,700 tokens。

- 走 **本地去背**：每張圖約 **6,000–8,000 tokens**
- 走 **remove.bg**：每張圖約 **12,000–15,000 tokens**

> 量產建議：分小批（每批 5–10 張）或開新對話，避免上下文累積導致成本暴增。

## 6. 風格基準（對齊現有素材）

- 風格：**像素藝術（pixel art）**，搭配熔岩/餘燼般的橘紅發光點綴（參考 `../DipanProj_Main/Assets/Resources/Weapon/weapon_sword.png` 等，路徑相對本檔所在的 `readme/`）。
- 世界觀：佛教 × 恐怖（燃燈古佛、隧道邪能、《無限恐怖》風），俯視角 2D。
- 規格：單體置中、透明背景、約正方形。現有 sprite 多為 RGBA，尺寸 500–1260px。
- 通用提示詞骨架（可依主題調整）：
  > `Pixel art game item icon, [主體描述], plain flat [背景色] background, single object centered, clean crisp pixel art, 2D top-down RPG asset`

## 7. 飛行道具專屬注意事項（只在產「會飛的投射道具」時適用）

> 燃燈計畫是彈道（ballistic）射擊遊戲，許多「武器」其實是會飛出去的子彈／投射物。

1. **主體必須是「會飛出去」的投射道具**，不是放在裝備欄的裝備。
   （例：彎刀飛劍、炸彈、法器、符咒、骨鏢、蜂窩彈… ✅；念珠手串那種偏「裝備」❌）
2. **道具上不要纏繞任何特效**。不要畫閃電、不要環繞火焰、不要拖尾、不要動態光效。
   原因：單張靜圖飛出去時特效不會動，反而很怪。**特效之後會另外做成影片動畫再加**，所以圖本身要乾淨單體。
3. 提示詞建議加上：`no glow, no motion effects` 並指定 `plain flat [灰/白] background` 方便本地去背。
4. 發想可以發散、多樣化（不同造型、材質、主題），使用者會再篩選。
